# Шашлычный рай · Shashlik Paradise

Демо интернет-магазина для Ахалкалаки. Контакт: +995 591 244 075. Интерфейс и названия 202 позиций: русский, грузинский, армянский, английский. Локально сохранены 157 фотографий из двух ресторанных каталогов.

**Это демо, а не готовый коммерческий магазин.** Демо не отправляет заказы, не списывает деньги и не уведомляет Telegram. Полный статус и ограничения: [docs/STATUS.md](docs/STATUS.md).

## Быстрый запуск

Требуется Python 3.12+. Установка зависимостей для сервера не нужна.

```bash
python3 run_demo.py
```

Открыть http://127.0.0.1:8000 . Демо-база создаётся отдельно в `data/demo.sqlite`. Настройки города, телефона и банковских ссылок: [demo/settings.json](demo/settings.json). Ссылки открывают страницы банков для ручного перевода; автоматической проверки оплаты нет. Во время показа демо деньги не переводить.

## Переносимое демо без сервера

```bash
python3 demo/export_preview.py
```

Распаковать созданный `dist/Шашлычный-рай-демо-4-языка.zip` целиком и открыть `index.html`. Каталог, корзина и расчёт застолья выполняются локально в браузере. Панель управления скрыта в этом варианте, так как требует серверного API.

## Исходные данные и пересборка каталога

```bash
python3 demo/build_catalog.py
```

Сборка воспроизводится из файлов репозитория; внешние сервисы, временные файлы и соседние папки не нужны.

- `demo/photo_sources.json`: исходные ссылки, названия, цены RUB и связь с фотографиями.
- `demo/source_metadata.json`: публичные метаданные блюд, включая вес там, где он найден.
- `demo/exchange_snapshot.json`: сохранённый ответ API Национального банка Грузии. Курс с 14.11.2026: 100 RUB = 3.154 GEL. Округление вверх до целого лари согласовано для демо. Это не автоматически обновляемый курс.
- `demo/translations.tsv`: переводы названий RU/KA/HY/EN.
- `static/media/`: локальные фотографии, имена по хешам исходных URL.

Себестоимость и остатки демо технические. Не использовать их для закупок и финансовых решений. У 92 позиций известен вес из источника; другие позиции не участвуют в расчёте мясных порций. Технические нормы 350 г/взрослый и 180 г/ребёнок ещё не утверждены рестораном. Подробные описания, состав и аллергены не полностью переведены; переводы названий требуют редакторской проверки.

Категория алкоголя предусмотрена. В собранных исходных данных алкогольные товары не обнаружены; вымышленные позиции не добавлялись.

## Серверное ядро

```bash
python3 server.py
```

Этот запуск использует отдельную `data/store.sqlite`, каталог по умолчанию пустой. Чтобы открыть административное API, задать `ADMIN_TOKEN` в защищённом окружении процесса и ввести его в окне управления. Без токена административное API закрыто. `.env.example` — шаблон; сервер сам не загружает `.env`.

Реализованы серверный расчёт цены, транзакционное резервирование готовых порций, защита от повторного заказа, статусы, отмена и возврат, снимок стоимости и упрощённый журнал начислений. Нет полного складского/бухгалтерского учёта, персональной авторизации/RBAC, CRM, бонусов, реальных поставщиков и курьеров. Стандартный Python HTTP-сервер предназначен только для локальной разработки. Публичный запуск требует отдельной подготовки.

## Telegram

Создать нового бота через официальный [BotFather](https://t.me/BotFather) из аккаунта владельца. Инструкция: [docs/TELEGRAM.md](docs/TELEGRAM.md). Токен хранить как `TELEGRAM_BOT_TOKEN` в защищённом окружении, не в исходниках или чате.

```bash
python3 telegram_setup.py
```

Команда проверяет только личность бота через `getMe`. Добавлен отдельный `telegram_bot.py`: запуск long polling и ответы на /start, /menu, /contact, /language. Постоянный хостинг и обработка реальных заказов пока не подключены.

## Проверки

```bash
python3 -m unittest discover -s tests -v
node --check static/app.js
node tests/test_languages.cjs
```

Python-тесты временно запускают сервер на 127.0.0.1; нужны разрешения на локальные сокеты. Node используется только для проверки JavaScript и локализации. Подробности испытаний — в docs/STATUS.md. Проверка Node VM не заменяет проверку настоящим браузером.

## Безопасность данных

Секреты, локальные базы, кэш Python, архивы и сгенерированная копия демо исключены через `.gitignore`. Настройки содержат предоставленные владельцем публичные банковские ссылки; секретных банковских API-ключей здесь нет. Для резервной копии локальной базы остановить сервер и скопировать файл в защищённое хранилище. Автоматическое резервирование пока не настроено.

Фотографии принадлежат правообладателям сайтов «Шашлык Машлык» и «Мясье Шашлык». Лицензия на коммерческое использование не получена. Не публиковать их как фотографии собственного ассортимента без разрешения. Действующие проекты этих магазинов и проекты владельца не изменялись. Production-публикация не выполнялась.

## Размещённая версия с сохранением заказов

Адрес: https://shashlichniy-ray-akhalkalaki.sredacommuniti.chatgpt.site . Сборка: `python3 worker/build.py`. Hosted Worker использует D1 binding `DB`, миграции в `drizzle/`. Runtime secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `OWNER_SETUP_HASH`; обычная настройка `STORE_URL`. Секреты задаются только защищёнными настройками Sites.

Этот вариант использует настоящее серверное API, сохраняет заказ, поддерживает идемпотентность и отслеживание. Банковская оплата требует ручной проверки владельцем. Источник ассортимента и цены остаются презентационными — не считать их подтверждённым предложением реальной кухни.

Права Telegram: `/orders` для владельца; `/invite supplier` и `/invite courier` создают одноразовые приглашения; после назначения сотрудника на заказ ему доступны только его задания и соответствующие смены статуса. Персональная ссылка привязки владельца не хранится в репозитории.

Для закрытого Sites development-проверки есть `telegram_relay.py`. Постоянный прямой webhook требует доступного извне HTTPS endpoint: `configure_telegram_webhook.py` сначала проверяет публичную доступность API и только затем регистрирует webhook. Код не переводит сайт в публичный режим сам.

Worker-тесты: `node tests/worker.test.mjs` (Node 24+, встроенный node:sqlite). Полный текущий статус и непройденные сценарии — в docs/STATUS.md.

## Обновлённый конструктор и исследования

См. [исследование порций и UX](docs/FEAST_RESEARCH.md) и [приоритет абсолютного вклада](docs/PRICING_POLICY.md). Конструктор собирает полный стол, показывает строки с фото/ценами, поддерживает замену и удаление, серверный пересчёт и объяснение превышения бюджета. Сочетания подбираются по совместимости и стилю напитка; подтверждённая себестоимость нужна для ранжирования по абсолютному денежному вкладу.

После удаления 16 повторов в каталоге 186 позиций. Хинкали, хачапури и супы вынесены в отдельные категории. Разные начинки/порции/способы приготовления сохраняются. Отчёт: demo/deduplication.json; старые ID доступны как aliases для корзин.

Для локального Python-сервера конструктор теперь использует тот же JS-модуль, что и размещённый Worker: кроме Python нужен Node.js. Это предотвращает расхождение алгоритмов. Проверки: `node tests/feast.test.mjs`, `node tests/test_feast_ui.cjs`, прежние Worker/Python-тесты.
