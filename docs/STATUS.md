## Мультивыбор алкоголя и подбор под целевой чек

Форма поддерживает одновременно вино, водку, коньяк/бренди, пиво и чачу, количество и конкретный товар или автоподбор для каждого вида. API принимает alcoholSelections; старые alcohol/alcoholBottles остаются совместимыми. Ошибочные, повторяющиеся виды, дробные и нулевые количества отклоняются. В результате каждая выбранная категория — отдельная строка. Замены ограничены тем же видом; объём и серверная цена после замены обновляются.

Бюджет стал целевой суммой: ограниченный поиск замен улучшает состав и подбирает чек ближе к бюджету, без превышения и увеличения количества алкоголя. Конкретная бутылка клиента сохраняется. У выбранных дополнительных групп можно менять товары; горячие порции не наращиваются для расходования денег. Возможное исключение опциональных частей видно. Неизвестная себестоимость не используется как нулевая. При известных затратах в диапазоне 95–100% — приоритет абсолютной прибыли. Поиск ограничен 1000 ценовыми состояниями; глобальная оптимальность не обещается.

По открытым ценам Alcorium добавлены Finlandia 1/0.7 л, Beluga Noble 0.5 л, Askaneli 3 года 0.5 л и Sarajishvili VSOP 0.7 л; цены и наличие явно демонстрационные. Всего 200 товаров, из них 14 алкогольных. Два гостя / 200 GEL / одна водка → 200 GEL с Beluga и полноценным составом еды; вино + водка → 200 GEL. Проверены 19 тестов планировщика, 6 Worker-тестов, включая путь multi-feast → quote → локальный заказ с обоими напитками, UI количества/замены/удаления/нескольких видов и четыре языка. ## Города Грузии: запуск только в Ахалкалаки — 16.11.2026

Единая конфигурация config/delivery.json: 34 города и населённых пункта с названиями на RU/KA/HY/EN, активен только akhalkalaki. В верхней строке — выбор города с поиском, закрытые направления видны как «Скоро» и недоступны для выбора. При оформлении город показан отдельно; закрытая строка не меняет город и не открывает корзину.

Worker и локальный сервер валидируют city_id по этой конфигурации до создания заказа; закрытые/неизвестные ID отклоняются без записи в БД. Для старых клиентов без city_id применяется активный город по умолчанию. Название подтверждённого города сохраняется префиксом адреса и автоматически попадает в существующие уведомления поставщику/оператору/курьеру; схема и исторические заказы не менялись. Отдельного city_id в исторической таблице пока нет. Это ограничение обслуживаемого города, не геокодирование улиц: адрес и возможность доставки внутри города по-прежнему согласовываются оператором.

Проверки: единственный активный город, локализация всех названий, поиск на другом языке, запрет выбора закрытой строки в UI, серверный отказ до записи для закрытых/поддельных ID, сохранение города в адресе и идемпотентность. Продакшен-заказы для проверки не создаются.
