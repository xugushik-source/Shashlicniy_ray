# Состояние этапов

1. Аудит — частичный, подтверждённые исходники и ограничения в AUDIT.md. Требуется дочитать Telegram, текущие SQL-функции заказов, платежи и политики доступа.
2. Архитектура — локальное транзакционное ядро и схема реализованы. Полная модель ролей, партий, рецептур, лояльности и интеграций впереди.
3. Магазин — каталог, поиск, корзина, оформление, упрощённый расчёт застолья и управление товарами. Нет полноценных карточек, комплектов, рекомендаций и всей главной страницы по ТЗ.
4. Заказы — серверная цена, идемпотентность, резерв, статусы, outbox. Нет поставщиков, курьеров, замен, реальных уведомлений, платежей и UI отслеживания/повтора.
5. Финансы/склад — готовые порции и упрощённый журнал. Нет полного учёта, фактической калькуляции, сырья, партий, расходов и денег.
6. CRM/маркетинг — не реализовано.
7. Тестирование — 12 автоматических тестов прошли: 8 ядра + 4 HTTP. Python compile и JS syntax прошли. HTTP проверен локальным subprocess на 127.0.0.1 с временной БД. Браузер, мобильные устройства, платёжные/Telegram сервисы не проверены.
8. Предрелиз — не пройден. Ни один из комплексных критериев ТЗ не считается полностью закрытым только на основании этих тестов.

## Размещённый сервер заказов — 15.11.2026

Адрес: https://shashlichniy-ray-akhalkalaki.sredacommuniti.chatgpt.site . Статическая версия заменена Worker ESM с отдельной Cloudflare D1. Миграции orders/events/notifications/telegram_users/telegram_updates/staff_invites/setup_claims применены публикацией Sites.

Живое API проверено защищённым служебным доступом: 202 позиции; POST /api/orders вернул 201 и создал явно помеченный тестовый заказ; повтор того же Idempotency-Key вернул тот же ID; отслеживание по секретному bearer-токену вернуло статус new. Банковские ссылки открываются для ручного перевода, без автоматического признания оплаты.

Роли в Telegram: владелец привязывается по персональной bootstrap-ссылке. /orders показывает заказы; владелец подтверждает и меняет статусы, создаёт одноразовые приглашения /invite supplier и /invite courier, назначает сотрудника на заказ. /tasks сотрудника показывает только его задания; поставщик видит состав и этапы приготовления, курьер — назначенный заказ и необходимые доставочные данные. Эти роли проверены локальными интеграционными тестами; полный живой путь с владельцем, поставщиком и курьером ещё требует их подключения.

Токен бота и webhook secret сохранены как runtime secrets в Sites, в исходниках их нет. Доступ сайта по-прежнему owner-private: запрошено явное разрешение открыть всем по ссылке, ответа пока нет. Для проверки закрытого сайта временно работает development relay к опубликованному webhook-обработчику. Это НЕ постоянный хостинг Telegram. Переход на прямой постоянный webhook подготовлен в configure_telegram_webhook.py и возможен после открытия сайта. От владельца ожидается нажатие Start в персональной ссылке для назначения получателя уведомлений.

Проверки: 23 Python-теста; 5 новых Worker-тестов через node tests/worker.test.mjs; проверка четырёх языков; успешные публикации и проверка существования D1-таблиц через native Sites. Браузерная проверка не проводилась — cua_repl отсутствует. Настоящие заказы сохраняются, но ассортимент и цены всё ещё презентационные и наличие не подтверждено реальной кухней. Полные склад, финансы, CRM, бонусы, отзывы, частичные возвраты и платёжный эквайринг пока не реализованы.
